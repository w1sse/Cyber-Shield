# Cyber-Shield: запуск и устройство

Нужен только Python 3.8+ (устанавливать пакеты не требуется).

```
python server.py        # Windows: py server.py
```
Откройте http://localhost:8000

## Что умеет сайт
- **Проверка угроз:** ссылки, QR-коды (камера или картинка), файлы, SMS, номера телефонов, пароли, IP.
- **Личный кабинет** (`account.html` → `dashboard.html`): регистрация и вход, уровень защиты, история проверок, график результатов, профиль, скачивание и удаление своих данных.
- **Академия** и **Чек-ап:** прогресс хранится в браузере, а после входа ещё и в кабинете (синхронизируется между устройствами).
- Три языка: русский, казахский, английский.

## Ключи для баз угроз (по желанию)
Без ключей всё работает, кроме сверки ссылок и файлов с базами угроз.

1. **Google Safe Browsing**: console.cloud.google.com → проект → включить *Safe Browsing API* → «Учётные данные» → «API-ключ».
2. **VirusTotal**: virustotal.com → профиль → *API key* (бесплатно, около 4 запросов в минуту).
3. Скопируйте `.env.example` в `.env`, впишите ключи, перезапустите сервер.
**Файл `.env` никому не отправляйте и не выкладывайте на GitHub. В `.env.example` ключей быть не должно.**

## Как это устроено
- `public/` — сайт. Страницы можно открыть и без сервера (`public/index.html`), но тогда не работают кабинет, сверка с базами и жалобы на номера.
- `server.py` — раздаёт сайт и отвечает на `/api/*`.
- `reports.db` — база SQLite: жалобы на номера, пользователи, сессии, история, прогресс.
- `public/qr.js` — собственный декодер QR-кодов (версии 1-10, этого хватает для ссылок). Если браузер умеет `BarcodeDetector`, используется он.

## Что куда отправляется
| Данные | Где обрабатывается |
|---|---|
| Текст SMS, изображение QR-кода, сам файл, пароль | только в браузере |
| Адрес ссылки (в том числе из QR и SMS) | сервер проекта → Google Safe Browsing и VirusTotal. Сервер сам ссылку **не открывает** |
| Отпечаток файла (SHA-256) | сервер проекта → VirusTotal. Файл не загружается |
| Номер телефона | сервер проекта (поиск жалоб); хранится как SHA-256 с солью |
| Пароль (по галочке) | на сторонний сервис Have I Been Pwned уходят только первые 5 символов SHA-1 хеша |

Если пользователь вошёл в кабинет, сервер сохраняет **краткие итоги**: тип проверки, уровень, подпись (домен ссылки, маскированный номер, имя файла, «Wi-Fi»/«text» для QR, оценка SMS). Тексты сообщений, содержимое QR-кодов и пароли не сохраняются.

## Безопасность
- Пароли хранятся как `scrypt` с индивидуальной солью. Сессии — случайный токен в cookie `HttpOnly; SameSite=Lax` (на сервере лежит только его хеш), срок 30 дней.
- Запросы кабинета принимаются только с того же адреса сайта и с заголовком `X-CS` (защита от подделки запросов с чужих сайтов). Для них CORS закрыт.
- Ограничения: вход — 10 попыток в 10 минут с IP и 5 на адрес почты; регистрация — 5 в час; ссылки и файлы — 20 в минуту.
- За HTTPS (nginx/Caddy) задайте `SECURE_COOKIES=1`. Без HTTPS камера работает только на `localhost`.
- Сервер слушает `127.0.0.1`. `HOST=0.0.0.0` откроет его для локальной сети: делайте так только осознанно.

## Что сказать на защите
- Отсутствие угроз в базах не доказывает безопасность: новые фишинговые сайты появляются раньше, чем попадают в базы.
- Открытой официальной базы мошеннических номеров в Казахстане нет, поэтому используются жалобы пользователей. Сначала база пустая.
- Оценка «Уровень защиты» в кабинете — это показатель подготовки пользователя (60% чек-ап и 40% академия), а не состояние устройства.
- «Помощник по ситуации» работает по заранее заданным правилам и не является искусственным интеллектом.
- Декодер QR проверен на сгенерированных кодах (в том числе с искажением, шумом и повреждениями), но в плохих условиях съёмки профессиональные библиотеки надёжнее.
